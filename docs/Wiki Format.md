# ARIES wiki: format and layout (accepted 2026-09-19, applied by `scratchpad/migrate-2026-09-19.py`)

The wiki is read by humans in Obsidian/Lapis and read *and written* by agents. Pages must survive moderate human edits without breaking the agents, and agent writes must never clobber human prose. This proposal has three parts: the principles that give edit-resistance, the directory layout, and the per-type page skeletons.

## Part 1 — Principles for edit-resistant markdown

1. **Frontmatter is the typed record.** Every page has a `type` and a `slug`; each type has a Pydantic schema. Parsers *preserve unknown keys* and *never silently fix* bad values — bad values go to the lint report.
2. **Sections are found by H2 title, not by position.** Titles are matched case-insensitively with a small alias list (`Open tasks` = `Tasks` = `To do`). Unknown sections are preserved verbatim. Section order is free.
3. **Every section has exactly one owner**, declared in the schema: `human` (agent never touches; may only Propose), `shared` (humans and agents both read and append; nobody deletes another's lines — every page has a shared `## Notes` as the catch-all), `managed` (agent rewrites wholesale), `append` (agent appends, humans may edit earlier lines), `derived` (regenerated from other pages; hand edits are lost and lint warns). Regeneration touches *only* derived sections.
4. **Managed and append regions are fenced with HTML comments** — invisible in Obsidian/Lapis reading view, unambiguous to code:
   ```markdown
   ## Open tasks
   <!-- watcher:managed -->
   - [ ] Book the seminar hall [owner:: aira] [due:: 2026-09-24] [src:: 3EB1A2] ^t-9f3c
   <!-- /watcher -->
   ```
   Text a human writes *inside* a fence is parsed back if it matches the grammar (e.g. ticking a box, changing a due date), otherwise preserved but flagged. Text *outside* fences is never touched.
5. **Line items carry identity.** Each item ends with an Obsidian block id (`^t-9f3c`). Identity is the id, not the text, so humans can reword a task and it stays the same task; `[[page#^t-9f3c]]` links to it natively. Metadata uses Dataview-style inline fields `[key:: value]` — a known convention, readable, and regex-parseable (`\[(\w+)::\s*([^\]]*)\]`).
6. **Pointers to WhatsApp are `[src:: <gowa message id>]`** (comma-separated if several). Any agent resolves them through the Gateway (`get_message`, `get_context(id, before, after)`).
7. **References are wikilinks everywhere — in frontmatter too** (`lead: "[[Devansh]]"`, `[owner:: [[Aira]]]`). Obsidian and Lapis treat property wikilinks as real links and rewrite them on rename, so references are rename-safe. Dates are ISO 8601; never display names in fields, never "next Friday".
8. **One canonical home per fact.** A member's project list, a project's thread list, the index pages — all *derived* and regenerated by a job. Nothing is hand-maintained in two places.
9. **Filename = title = the thing you link.** `slug` is a stable URL-safe id kept in frontmatter for code; humans never type it. Filenames avoid the characters Obsidian forbids (`: ? * " < > | \ /`).
10. **Every agent write is read-modify-write against a Lapis `baseRevision`.** A collision produces a Conflict Note, never a silent overwrite; the lint job surfaces `.sync-conflicts/`.
11. **Round-trip idempotency is tested.** For every page type: parse → dump → parse yields the same model *and* the same bytes for untouched sections. This is the CI test that keeps agents from slowly mangling pages.
12. **Lint reports; it does not repair** — except purely additive defaults (a missing optional key, a missing managed section skeleton).
13. **Agents change pages only through the page editor** (`shared/wiki/editor.py`). It checks each write against the section's owner, touches only the fenced region, inserts a missing section at its schema position, escapes headings and fence markers in whatever it writes (so model output can't open a section or close a fence), and re-validates frontmatter after every change.

## Part 2 — Directory layout

```
/
├── README.md                    derived — this week across ARIES (dashboard for humans)
├── AGENTS.md                    human — what this vault is and the rules for agents and humans
├── Members.md  Projects.md  Events.md  Resources.md   derived indexes (generated from frontmatter)
├── people/<slug>.md             type: member      (flatten; team/wing already in frontmatter; drop empty members/)
├── projects/<slug>.md           type: project
├── projects/<slug>/…            optional folder: attachments, ideas.md, anything humans want alongside
├── events/<slug>.md             type: event
├── channels/<channel>.md        type: channel     (index of threads)
├── channels/<channel>/<thread-id>.md        type: thread  (active + stale)
├── channels/archive/<channel>/<thread-id>.md            (ended → moved here; Lapis rewrites links)
├── resources/<slug>.md          type: resource    (typed: url, kind, related)
├── research/digests/<date>.md   type: digest      (Research Agent output)
├── innovation/<date>-<slug>.md  type: idea        (Innovation Agent output)
├── inbox/<agent>.md             type: inbox       (an agent's Inbox - the source of truth, ADR-0014)
└── meta/
    ├── channels.md              derived — Allowlist mirror (group JIDs are fine here)
    ├── agents/<agent>.md        derived — what the agent does, schedule, run ledger tail
    ├── schema/<type>.md         human — the page format for each type (canonical; code follows these)
    ├── skills/<skill>/SKILL.md  shared — agent skills loadable from the wiki
    ├── audit/<yyyy-mm>.md       append — outbound messages sent, by whom, to where
    ├── lint.md                  derived — validation report
    └── config.md                human — Bot Admins, thresholds that humans may tune
```
Attachments: `projects/attachments/` today → per-initiative folder (`projects/<slug>/`) so a project is deletable/archivable as a unit.

## Part 3 — Page skeletons

Common frontmatter on every page: `type`, `slug`, `title`, `created`, `updated`, `updated_by` (`human` | agent name), `tags`.

### member (`people/<Title>.md`)
```markdown
---
type: member
slug: aira
title: Aira
role: Executive            # OC | Co-OC | Research Lead | Coordinator | Research Coordinator | Executive | Research Executive | Alumni
status: active             # active | alumni
whatsapp: unlinked         # linked | unlinked — never an id
---
# Aira
## About            human   (areas of interest, background)
## Projects         derived
## Past projects    derived
## Open tasks       derived
## Notes            shared
```
No team/wing (role is enough), no contact details, no socials: member details live in the member database, which every agent can query through a tool. Seeded from the team CSV into `~/projects/watcher-seed/members.json` (outside the vault).

### project (`projects/<slug>.md`) — an Initiative
```markdown
---
type: project
slug: watcher
title: Watcher
status: active             # proposed | active | paused | done | dead
lead: "[[Devansh]]"
members: ["[[Devansh]]", "[[Aira]]"]
channel: "[[Watcher (WhatsApp)]]"   # optional
started: 2026-09-03
target: 2026-12-15
category: Internal         # keep today's categories
repos: [https://github.com/…]
kanban:                    # GH Projects URL, later
health: 0.82               # managed by Project Agent
health_updated: 2026-09-19
---
# Watcher
## Brief            human   (agent may Propose edits; may use ### headings inside)
## Status           managed (≤5 sentences, rewritten by Project Agent each run)
## Open tasks       managed (items: `- [ ] text [owner:: slug] [due:: date] [src:: id] ^t-xxxx`)
## Decisions        append  (`- 2026-09-19 — text [by:: slug] [src:: id] ^d-xxxx`)
## Log              append  (`- 2026-09-19 — text [src:: id]`; one line per notable update)
## Resources        append  (`- [[resource-slug]] — why it matters [src:: id]`)
## Threads          derived (links to channel threads whose `initiative` is this project)
## Notes            shared
```

### event (`events/<slug>.md`) — an Initiative
Same frontmatter as project minus `repos/kanban/health`, plus `event_type`, `date`, `end_date`, `venue`, `registrations` (URL), `budget`. Sections: `Brief` (human), `Status` (managed), `Logistics` (managed checklist items), `Decisions`, `Log`, `Resources`, `Threads`, `Outcome` (human, filled after the event), `Notes` (shared).

### channel (`channels/<channel>.md`)
```markdown
---
type: channel
slug: watcher
title: Watcher (WhatsApp)
kind: project              # coordis | exes | research | all | project | event | other (one channel each of the first four)
initiative: "[[Watcher]]"     # when kind is project/event
cursor: 3EB1…              # last processed message id
last_batch: 2026-09-19T09:41:00+05:30
---
# Watcher (WhatsApp)
## Active threads   derived  (`- [[channels/Watcher (WhatsApp)/20260918-demo-date|Moving the demo to Friday]] — last 2026-09-19`)
## Stale threads    derived
## Archived threads derived
## Notes            shared
```
No prose. JIDs live in `meta/channels.md`, not here.

### thread (`channels/<channel>/<thread-id>.md`)
```markdown
---
type: thread
slug: 20260918-demo-date
channel: "[[Watcher (WhatsApp)]]"
initiative: "[[Watcher]]"     # optional
title: Moving the demo to Friday
state: active              # active | stale | ended
opened_at: 2026-09-18T10:02:00+05:30
last_message_at: 2026-09-19T09:41:00+05:30
participants: ["[[Devansh]]", "[[Aira]]"]
message_ids: [3EB0…, 3EB1…]
continues:                 # thread slug this one continues, if any
summary_cursor: 3EB1…
---
# Moving the demo to Friday
## Summary          managed (2–5 sentences)
## Items            managed
- [ ] Book the seminar hall [kind:: task] [owner:: [[Aira]]] [due:: 2026-09-24] [src:: 3EB1A2] ^i-9f3c
- [x] Demo moves to Friday 26 Sep [kind:: decision] [src:: 3EB0C1, 3EB0C2] ^i-1a2b
- https://… — slide template [kind:: resource] [src:: 3EB2D3] ^i-77e0
- Is the projector fixed? [kind:: question] [by:: [[Devansh]]] [src:: 3EB3E4] ^i-b0b0
## Timeline         append   (every line carries a [src:: id] so any agent can go back to the conversation)
- 2026-09-18 10:02 — [[Devansh]] proposes Friday [src:: 3EB0C1]
- 2026-09-19 09:41 — [[Aira]] agrees, will book the hall [src:: 3EB1A2]
## Notes            shared
```
`ended` is set only by a human, by editing `state:` in the wiki. Every Sunday the bot posts to the coordis Channel: "There are N stale threads, M of them with no messages in the last 7 days — please mark ended ones." The WhatsApp Agent then moves ended threads to `channels/archive/<Channel>/`.

### resource (`resources/<slug>.md`)
Frontmatter: `kind` (`paper | repo | talk | article | note`), `url`, `related` (initiative slugs), `added_by`. Sections: `Summary` (managed if agent-added, human otherwise), `Notes` (human). Today's freeform notes become `kind: note` with their text under Notes.

### inbox (`inbox/<agent>.md`) — the agent's Inbox (ADR-0014)
Frontmatter: `agent`. Written only through `shared/inbox`.
```markdown
## Pending          managed   (what the agent still has to do, oldest first)
- [ ] Thread update: Moving the demo to Friday [kind:: thread_update] [channel:: 1203...@g.us] [slug:: 20260918-demo-date] [since:: 3EB1A2] [thread:: [[channels/watcher/20260918-demo-date]]] [posted:: 2026-09-19T09:45:00+00:00] ^n-4f1a09c2
- [ ] Please re-check the budget          ← a human may add a line by hand; it's picked up as a request
## Done             managed   (acknowledged after the work succeeded; last 50 kept)
- [x] Thread update: Booking the hall [kind:: thread_update] … [done:: 2026-09-19T09:47:00+00:00] ^n-77c0e1d3
## Notes            shared
```
`[trigger:: now]` marks work the agent should do immediately rather than on its next scheduled run.

### meta/agents/<agent>.md — derived
Purpose, inputs, outputs, schedule, and the last 20 rows of the run ledger (started, finished, outcome).
